## 一、系统概览

### 1.1 功能定位

互助站（MutualAidStation）是家园玩法中的「NPC 每日委托订单」系统。玩家与 NPC 交互后，可以：

1. **查看**每天刷新的多个 NPC 委托订单（带星级、解锁条件、倒计时）。
2. **提交**订单所需材料（分两种类型：固定材料 `Fixed` / 自选材料 `Custom`）。
3. **刷新**不满意的订单（每日有次数上限，且需完成新手订单后解锁）。
4. 完成后获得**基础奖励 + 额外奖励**（额外奖励分 1~4 档）。

### 2.5 Model 生成（行 225~261）

```ts
private async generateModel(): Promise<void> {
    this.generateNextDayUpdateEntrustTimer();   // 先建立零点刷新定时器

    let data = await this.requestAllData();     // 请求全量订单数据（GET_INFO）
    if (data == null) return;                   // 请求失败直接返回

    // 回填模型顶层字段
    this._mutualAidStationModel.isUnlocked = this.checkifOrderUnlock();              // 本地检测是否已建造互助站
    this._mutualAidStationModel.isCompletedNewbieEntrusts = data.bNewbieOrderAllFinished;  // 新手订单是否完成
    this._mutualAidStationModel.isDailyRefreshUpper = data.bRefreshLimitReached;    // 刷新次数是否达上限
    this._mutualAidStationModel.extraRewardCount = data.iDailyRewardNum;            // 额外奖励已领次数
    this._mutualAidStationModel.extraRewardLimit = data.iExtraRewardMaxNum;         // 额外奖励上限
    this._mutualAidStationModel.extraRewardGrade = data.iExtraRewardGrade;          // 额外奖励档次

    // 若新手订单已完成，广播新手订单完成事件
    if (this._mutualAidStationModel.isCompletedNewbieEntrusts) {
        this.eventSys.triggerEventScopped(EventType.Default, TKPartyGameSystemEventDefine.TKPGOrderNewBieOrderComplete, TKPartyGameSystemEventScope);
    }

    // 清空并重建订单列表
    this._mutualAidStationModel.entrusts.length = 0;
    for (let index = 0; index < data.vecDailyOrder.length; index++) {
        const element = data.vecDailyOrder[index];
        if (element == null) continue;
        let entrust = this.generateEntrust(element, this._mutualAidStationModel.extraRewardGrade);
        if (entrust == null) continue;
        this._mutualAidStationModel.entrusts.push(entrust);
    }

    // 触发 ModelUpdate 事件（needImmediateRefrsh = true 表示需要当场刷新 UI）
    this.needImmediateRefrsh = true;
    this.eventSys.triggerEventScopped(EventType.Default, TKPartyGameSystemEventDefine.ModelUpdate, TKPartyGameSystemEventScope, this.needImmediateRefrsh);
    this.needImmediateRefrsh = false;
}
```

### 2.6 订单数据转换 generateEntrust（行 263~309）

这是把 `SOCClient.ITDailyOrderNode`（网络协议对象）转换成前端 `MutualAidStationEntrust`（Model）的核心函数：

```ts
private generateEntrust(node: SOCClient.ITDailyOrderNode, level: number): MutualAidStationEntrust | null {
    if (node == null) return null;

    let entrust: MutualAidStationEntrust = {
        npcId: node.iNpcID,                          // NPC ID
        index: node.iIndex,                          // 订单索引（0-based）
        star: node.iStar,                            // 星级
        conditionId: node.iConditionID,              // 条件 ID（关联配置表 DailyOrderCondition）
        preStatus: node.eState,                      // 上一次状态（用于检测状态边沿）
        status: node.eState,                         // 当前状态
        unlockCondition: { key: EMutualAidStationEntrustUnlockCondition.Level, value: node.iUnlockHomelandLevel },  // 解锁条件=愉悦等级
        countdown: Math.max(Number(node.lRefreshEndTime) - Number(this.getLocalTime()), 0),  // 倒计时（毫秒，取非负）
        endtime: BigIntUtils.LongToBigInt(node.lRefreshEndTime),   // 刷新结束时间（bigint）
        rewards: [],                                 // 奖励列表
        submit: { type: node.stCondition?.iType },   // 提交类型（Fixed/Custom）
        materials: [],                               // 材料列表
        isNewBieEntrust: !this._mutualAidStationModel.isCompletedNewbieEntrusts,  // 是否新手订单
    }

    // 若订单已无剩余次数（NO_REMAINING），结束时间改为下一刷新时刻
    if (entrust.status == SOCClient.E_DAILY_ORDER_STATE.E_DAILY_ORDER_STATE_NO_REMAINING) {
        entrust.endtime = BigIntUtils.LongToBigInt(this.getNextDayUpdateEntrustTime());
    }

    this.generateRewards(entrust, node.stCondition, level);   // 生成奖励
    this.generateMaterials(entrust, node.stCondition);        // 生成材料

    // 固定材料类型：填充材料已有数量
    if (entrust.submit.type == EMutualAidStationEntrustSubmitType.Fixed) {
        let materials = this.getSubmitFixedMaterials(entrust);
        entrust.materials.length = 0;
        if (materials != null && materials.length > 0) {
            for (let index = 0; index < materials.length; index++) {
                const element = materials[index];
                if (element == null) continue;
                let template = this.StorageBoxSys?.getTotalItemCountById(element.ItemID);  // 查背包+存储箱总持有量
                if (!template) continue;
                this.onUpdateEntrustMaterials(entrust, template.itemID, template.itemCount, element.ItemNum);
            }
        }
    }
    return entrust;
}
```

### 2.7 奖励生成（行 311~351）

```ts
private generateRewards(entrust, condition: SOCClient.ITDailyOrderCondition, level: number): void {
    if (condition == null || condition.vecBaseRewardItem == null) return;
    entrust.rewards.length = 0;
    this.pushRewards(entrust, condition.vecBaseRewardItem, false);  // 基础奖励

    // 额外奖励：level 1~4 对应不同字段
    if (level > 0 && level <= 4) {
        const extraRewardMap: Record<number, any[]> = {
            1: condition.vecExtraRewardItemOne,
            2: condition.vecExtraRewardItemTwo,
            3: condition.vecExtraRewardItemThree,
            4: condition.vecExtraRewardItemFour,
        };
        const extraRewards = extraRewardMap[level];
        if (extraRewards != null) {
            this.pushRewards(entrust, extraRewards, true);  // isExtra = true
        }
    }
}

private pushRewards(entrust, rewards: SOCClient.ITWarehouseItem[], isExtra: boolean): void {
    for (let index = 0; index < rewards.length; index++) {
        const element = rewards[index];
        if (element == null) continue;
        let item: MutualAidStationEntrustAward = {
            ItemID: element.iItemID,        // 物品 ID
            ItemNum: element.iItemCount,    // 物品数量
            ShowDirection: CalculationPositionDirection.RightPriority,  // 详情展示方位
            IntervalDistance: 0,
            isExtra: isExtra,               // 是否额外奖励
        }
        entrust.rewards.push(item);
    }
}
```

### 2.8 材料生成（行 353~378）

```ts
private generateMaterials(entrust, condition: SOCClient.ITDailyOrderCondition | null): void {
    entrust.submit.type = condition.iType;  // 提交类型（1=Fixed, 2=Custom）
    if (!entrust.submit.SpecifyItemIds) entrust.submit.SpecifyItemIds = observable([]);
    entrust.submit.SpecifyItemIds.length = 0;
    entrust.submit.TotalNumber = 0;
    if (!entrust.submit.SpecifyItemAndCount) entrust.submit.SpecifyItemAndCount = observable([]);
    entrust.submit.SpecifyItemAndCount.length = 0;

    // Fixed：vecItem = 指定物品+数量（iItemID + iItemCount）
    if (condition?.vecItem?.length > 0) {
        for (const item of condition?.vecItem) {
            entrust.submit.SpecifyItemAndCount.push({ iItemID: item.iItemID, iItemCount: item.iItemCount })
        }
    }

    // Custom：vecItemID = 可自选的物品 ID 白名单
    if (condition?.vecItemID?.length > 0) {
        for (const id of condition?.vecItemID) {
            entrust.submit.SpecifyItemIds.push(id);
        }
    }

    // Custom 需要的总数量
    if (condition?.iTotalItemNum > 0) {
        entrust.submit.TotalNumber = condition.iTotalItemNum;
    }
}
```

> **Fixed vs Custom 的区别**：
> - `Fixed`（类型 1）：材料是**服务器指定**的固定物品和数量（`vecItem`），客户端不需要也不能自选。
> - `Custom`（类型 2）：服务器只给一个**白名单**（`vecItemID`）和**总数量**（`iTotalItemNum`），玩家从白名单里自选任意组合凑够总数量。

### 2.11 零点刷新定时器（行 562~701）

这是系统里最复杂的一段，处理「每天凌晨自动刷新订单」的时序问题：

```ts
private getServerTime(): bigint {  // 获取服务器时间（毫秒，bigint）

    const timeSyncSys = Framework.getObject<ITimeSyncServerSystem>(this.getWorld(), GAME_OBJECT_TYPES.TimeSyncServerSystem);

private getLocalTime(): number { return Date.now(); }  // 本地时间（毫秒）

public getCountDownWithEndTime(entrust): number {
    let CurTime = Number(this.getLocalTime());
    let nowDate = new Date(CurTime);
    if (entrust.status == E_DAILY_ORDER_STATE_NO_REMAINING) {
        // 无剩余次数：返回距离下一次刷新的秒数
        const target = new Date(CurTime);
        target.setHours(DAILY_REFRESH_HOUR, 0, 0, 0);  // 今天 0 点
        if (nowDate.getTime() >= target.getTime()) target.setDate(target.getDate() + 1);  // 已过 0 点则明天
        return Math.floor((target.getTime() - nowDate.getTime()) / 1000);
    } else {
        // 正常：endtime（bigint，秒级？）减去当前时间
        const delay = (Number(entrust.endtime) - CurTime / 1000);
        return delay;
    }
}
```

> ⚠️ **注意**：`getCountDownWithEndTime` 里 `endtime` 与 `CurTime/1000` 相减，说明 `endtime` 是**秒级**时间戳；但 `generateEntrust` 里 `countdown` 用的是 `lRefreshEndTime - Date.now()`（毫秒级）。两处单位可能不一致，是潜在 bug 点（详见 §2.6 的 `countdown` 与这里 `endtime` 的语义差异）。

零点刷新定时器（行 638~678）：

```ts
private generateNextDayUpdateEntrustTimer(): void {
    this.destroyNextDayUpdateEntrustTimer();  // 先销毁旧的
    const timemout = () => {
        const time = this.getNextDayUpdateEntrustTime();  // 距离下一次刷新的秒数
        if (time < 10) {  // 距离零点不足 10 秒
            // 销毁轮询 timer，零点后延迟 3 秒再请求
            this.destroyNextDayUpdateEntrustTimer();
            const delayMs = (time + MIDNIGHT_DELAY_S) * 1000;
            this._midnightRetryCount = 0;
            const doRequest = async () => {
                // 用 "npcId:index:conditionId" 三元组签名判断数据是否真正变化
                const preSig = this._mutualAidStationModel.entrusts.map(e => `${e?.npcId ?? 0}:${e?.index ?? 0}:${e?.conditionId ?? 0}`).join(',');
                await this.generateModel();  // 重新拉数据
                const postSig = this._mutualAidStationModel.entrusts.map(...).join(',');
                if (preSig !== postSig) {
                    // 数据变了 → 刷新成功，弹 toast
                    this._midnightRetryCount = 0;
                    if (this.isMutualAidStationWindowOpen()) this.generateToast(EMutualAidStationToastType.RefreshSuccess);
                    this.tipSys.showToast(`今日订单已刷新`);
                } else {
                    // 数据没变 → 可能是服务器还没切数据，重试
                    if (this._midnightRetryCount >= MIDNIGHT_RETRY_MAX) { this._midnightRetryCount = 0; return; }
                    this._midnightRetryCount++;
                    this._midnightRequestTimer = UETimer.setTimeout(this.getTimerCtx(), doRequest, MIDNIGHT_RETRY_INTERVAL_MS);
                }
            };
            this._midnightRequestTimer = UETimer.setTimeout(this.getTimerCtx(), doRequest, delayMs);
        }
    }
    // 每 10 秒轮询一次，检查是否快到零点
    this._nextDayUpdateEntrustsTimer = UETimer.setInterval(this.getTimerCtx(), timemout, 10000);
}
```

> **零点刷新设计的精妙之处**：
> 1. 用 10 秒的 `setInterval` 轮询「距离零点还有多久」，避免为一个一天只发生一次的事件长期持有精确定时器。
> 2. 快到零点时（<10 秒），转成一次性 `setTimeout`，延迟「剩余时间 + 3 秒」后请求，给服务器留 3 秒完成数据切换。
> 3. 请求后比较「请求前后订单签名（npcId:index:conditionId）」，若没变化说明服务器还没切数据，最多重试 6 次（每次间隔 3 秒）。
> 4. `destroyNextDayUpdateEntrustTimer` 里**故意不**连 `_midnightRequestTimer` 一起清，注释说明：因为 `generateModel()` 会重新触发 `generateNextDayUpdateEntrustTimer()`，若连带清掉重试 timer 会中断重试链。

```ts
    for (let entrust of this._mutualAidStationModel.entrusts) {
        if (entrust.submit.type == Fixed) {
            for (const iteminfo of entrust.submit.SpecifyItemAndCount) items.push(iteminfo.iItemID);

    if (entrust.status != RUNNING && entrust.status != INIT) return false;
    if (entrust.submit.type == Fixed) {
        // 逐项检查持有量 >= 需求量
        for (const element of entrust.submit.SpecifyItemAndCount) {
            let curOwningNum = this.StorageBoxSys.getTotalItemCountById(element.iItemID).itemCount;
            if (curOwningNum < element.iItemCount) return false;
        }
    }
    if (entrust.submit.type == Custom) {
        // 白名单内所有物品持有量之和 >= 总需求数
        let summary = 0;
        for (const element of entrust.submit.SpecifyItemIds) {
            summary += this.StorageBoxSys.getTotalItemCountById(element).itemCount;
        }
        return summary >= entrust.submit.TotalNumber;
    }
    return true;
}
```

```ts
private onMutualAidStationEntrustsChanged(param: EventParam): void {
    let data = param as SOCClient.TDailyOrderNotifyInfoChange;
    if (data == null) return;

    // 1. 更新顶层字段
    this._mutualAidStationModel.isDailyRefreshUpper = data.bRefreshLimitReached;
    this._mutualAidStationModel.extraRewardCount = data.iDailyRewardNum;
    this._mutualAidStationModel.extraRewardLimit = data.iExtraRewardMaxNum;
    this._mutualAidStationModel.extraRewardGrade = data.iExtraRewardGrade;

    // 2. 新手订单完成边沿检测（旧值 false → 新值 true）
    let oldNewBieEntrust = this._mutualAidStationModel.isCompletedNewbieEntrusts;
    let newNewBieEntrust = data.bNewbieOrderAllFinished;
    if (newNewBieEntrust == true) {
        this.eventSys.triggerEventScopped(..., TKPGOrderNewBieOrderComplete, ...);  // 广播新手完成
    }
    if (oldNewBieEntrust == false && newNewBieEntrust == true) {
        this.wwiseSystem.postEvent(EWwiseEvent.Play_Homeland_Order_Complete_Beginner);  // 播放音效
        this.tipSys.showToast(CommonUIUtil.getTextByID(this.getWorld(), 10609));
    }
    this._mutualAidStationModel.isCompletedNewbieEntrusts = data.bNewbieOrderAllFinished;

    // 3. 遍历 vecDailyOrder 逐项更新（原地更新，保持 observable 引用）
    let TodayAllFinish: boolean = true;
    for (let index = 0; index < data.vecDailyOrder.length; index++) {
        const element = data.vecDailyOrder[index];
        if (element == null) continue;

        // 列表长度不足时先 push 一个空占位对象
        if (this._mutualAidStationModel.entrusts.length <= index) {
            this._mutualAidStationModel.entrusts.push({ /* 全零初始对象 */ });
        }
        let entrust = this._mutualAidStationModel.entrusts[index];
        entrust.countdown = Math.max(Number(element.lRefreshEndTime) - Number(this.getLocalTime()), 0);
        entrust.npcId = element.iNpcID;
        entrust.conditionId = element.iConditionID;
        entrust.star = element.iStar;
        entrust.preStatus = entrust.status;   // 记录旧状态（用于 UI 边沿动画）
        entrust.status = element.eState;      // 更新新状态
        entrust.unlockCondition = { key: Level, value: element.iUnlockHomelandLevel };
        entrust.isNewBieEntrust = !this._mutualAidStationModel.isCompletedNewbieEntrusts;

        // 无剩余次数时 endtime 设为下一刷新时刻，否则用服务器返回的刷新结束时间
        if (entrust.status == E_DAILY_ORDER_STATE_NO_REMAINING) {
            entrust.endtime = BigIntUtils.LongToBigInt(this.getNextDayUpdateEntrustTime());
        } else {
            entrust.endtime = BigIntUtils.LongToBigInt(element.lRefreshEndTime);
            TodayAllFinish = false;
        }

        this.generateMaterials(entrust, element.stCondition);
        this.generateRewards(entrust, element.stCondition, this._mutualAidStationModel.extraRewardGrade);

        // Fixed 类型：重新填充材料持有量
        entrust.materials.length = 0;
        if (entrust.submit.type == Fixed) {
            let materials = this.getSubmitFixedMaterials(entrust);

                }
```

实例方法（带超时+重试）：

```ts
public async sendServerRequest<T>(scope, messageId, options): Promise<RequestRet<T>> {
    const finalOptions = { ...DEFAULT_OPTIONS, ...options };  // 合并默认（2s 超时/3 次重试/1s 延迟/可靠传输）
    let requestId = this.generateRequestId();
    const request: RequestInfo = { requestId, scope, messageId, timestamp: Date.now(), retryCount: 0, options: finalOptions };
    this.requestMap.set(requestId, request);

    return new Promise((resolve, reject) => {
        this.eventManager.once(scope, requestId, (ret) => {  // 一次性回调
            resolve({ ...ret, data: ret.data ? ret.data : undefined });
        }, this);
        this.sendRequest(request);  // 实际发送
    });
}

private sendRequest(request): void {
    // 设置超时定时器（timeoutSeconds 秒）
    request.timeoutHandle = UETimer.setTimeout(this, () => this.handleTimeout(request.requestId), request.options.timeoutSeconds * 1000);
    // 序列化 data 并 RPC 发送
    const reqData = request.options.data ? FrameworkUtils.stringify(request.options.data) : "";
    if (request.options.reliable) {
        this.ServerCall(request.requestId, request.scope, request.messageId, reqData);
    } else {
        this.UnreliableServerCall(...);
    }
}
```

超时重试（handleTimeout）：

```ts
private handleTimeout(requestId): void {
    const request = this.requestMap.get(requestId);
    if (!request) return;
    if (request.retryCount < request.options.maxRetries) {  // 未达重试上限
        request.retryCount++;
        request.retryHandle = UETimer.setTimeout(this, () => this.sendRequest(request), request.options.retryDelaySeconds * 1000);
    } else {
        // 超过最大重试 → 通知失败
        this.clientHandleRequestComplete(requestId, { retCode: -1, message: "Request timeout after retries" });
    }
}
```

RPC 定义：


### 5.3 DS 侧请求分发

文件：`Hearthbound/.../Mediator/MediatorDSSystem.ts`

```ts
public handleRequest(uid, requestId, scope, messageId, data): void {
    this.processRequest(uid, requestId, scope, messageId, data);
}

private async processRequest(uid, requestId, scope, messageId, data): Promise<void> {
    // 1. 先找注册的 message handler（按 scope + messageId）
    const { target, handler } = this.getMessageHandler(scope, messageId) || { target: null, handler: null };
    if (handler) {
        retInfo = await handler.call(target, uid, data);  // 调用处理器
    } else {
        // 2. 否则找 scope 的 event processor
        const processor = this.processorMap.get(scope);
        if (processor) retInfo = await processor.onReceiveMessage(uid, messageId, data);
        else retInfo = { retCode: -1, message: "no processor with scope " + scope };
    }
    // 3. 通过 mediatorMap 找该 uid 的 mediator，回传结果
    const mediator = this.mediatorMap.get(uid);
    mediator.handleRequestComplete(requestId, retInfo);  // 回传给 client
}
```

> 互助站请求的 handler 注册在 `StorageBoxDSSystem`（通过 `registerMediatorHandlers` 机制 + `@MediatorMessageHandler` 装饰器），分发的入口在 `StorageBoxDSSystem` 的 `onReceiveMessage`（或类似 switch 结构），根据 `ServerRequestId.FinishMutualAidStationEntrust` 路由到对应函数。

### 6.2 主流程 finishMutualAidStationEntrust

```ts
public async finishMutualAidStationEntrust(uid, iOrderConditionID, clientItems): Promise<RequestRet> {
    // 1. 参数校验
    if (iOrderConditionID <= 0) return { retCode: StorageBox_FinishMutualAidStationEntrustFailed, message: "Invalid iOrderConditionID" };

    // 2. 读配置表：DailyOrderCondition
    const orderCondition = this.dataCenterSys.getOrderDescByConditionId(iOrderConditionID);
    if (!orderCondition) return { retCode: ..., message: "Order condition not found" };

    const submitType = orderCondition.iType | 0;               // 1=Fixed, 2=Custom
    const conditionDetail = orderCondition.sConditionDetail || "";  // 材料明细字符串

    // 3. 按类型解析待扣清单
    let resolved;
    if (submitType === Fixed) {
        resolved = this.resolveFixedSubmitItems(uid, iOrderConditionID, conditionDetail);
    } else if (submitType === Custom) {
        resolved = this.resolveCustomSubmitItems(uid, iOrderConditionID, conditionDetail, clientItems);
    } else {
        return { retCode: ..., message: "Unsupported submit type" };  // 未知 type 一律拒
    }
    if (!Array.isArray(resolved)) return resolved;  // resolver 返回错误对象则透传

    const itemsToConsume = resolved;

    // 4. 扣材料：removeItemsPreferBag（背包优先 → 不足扣存储设施）
    const consumeRet = await this.removeItemsPreferBag(
        uid, itemsToConsume,
        RequestSource.MutualAidStation,                                       // 来源标记
        SOCClient.E_SCENES_CHANGE_ITEM.E_SCENES_CHANGE_ITEM_DAILY_ORDER,      // 场景
        SOCClient.E_SUB_SCENES_CHANGE_ITEM.E_SUB_SCENES_CHANGE_ITEM_DAILY_ORDER_NPC_SUBMIT,  // 子场景
    );
    if (consumeRet.retCode !== Game.ErrorCode.Success) return consumeRet;  // 扣料失败直接返回

    // 5. 上报 GS：TDailyOrderFinishConditionDSReq（只带 lUid + iOrderConditionID）
    const req = SOCClient.TDailyOrderFinishConditionDSReq.create({
        lUid: BigIntUtils.BigIntToLong(uid),
        iOrderConditionID: iOrderConditionID,
    });
    const result = await this.request<TDailyOrderFinishConditionDSRsp>(
        SOCClient.E_SVR_MSG_ID.E_SVR_MSG_ID_DAILY_ORDER_FINISH_CONDITION_DS,  // 6717
        req,
        { connectionTag: NetworkUrlDefine.DS2DSM },  // DS 直连 DSM（GS）
    );
    if (!ProtoUtils.isValidResponse(result)) {
        // 扣料已生效，上报失败仅记 error 不回滚（GS 有重连/补单兜底）
        LoggerUtils.error(...);
    }

    // 6. 返回成功（材料已扣，UI 继续走完成流程）
    return { retCode: Game.ErrorCode.Success };
}
```

> **关键设计**：`sConditionDetail` 是配置表 `DailyOrderCondition` 里的一个字符串字段，编码了材料明细：
> - Fixed：`"itemId|count;itemId|count;..."`（如 `935018|1;930067|2`）
> - Custom：`"totalNumber;itemId1|itemId2|..."`（如 `6;1000001|1000002|1000003|...`）

### 6.3 Fixed 类型解析 resolveFixedSubmitItems

```ts
private resolveFixedSubmitItems(uid, iOrderConditionID, conditionDetail): ITWarehouseItem[] | RequestRet {
    const parsed = this.parseFixedConditionDetail(conditionDetail);  // 解析 "itemId|count;..."
    if (parsed.length === 0) {
        return { retCode: ..., message: "Fixed conditionDetail empty/invalid" };
    }
    return parsed;  // clientItems 在此分支被忽略（防篡改）
}

private parseFixedConditionDetail(detail: string): ITWarehouseItem[] {
    const result = [];
    if (!detail) return result;
    const entries = detail.split(';');
    for (const entry of entries) {
        const trimmed = entry.trim();
        if (!trimmed) continue;
        const parts = trimmed.split('|');
        if (parts.length !== 2) { LoggerUtils.warn(`skip malformed "${trimmed}"`); continue; }
        const itemId = parseInt(parts[0], 10);
        const count = parseInt(parts[1], 10);
        if (itemId <= 0 || count <= 0) continue;
        result.push({ iItemID: itemId, iItemCount: count });
    }
    return result;
}
```

### 6.4 Custom 类型解析 resolveCustomSubmitItems

```ts
private resolveCustomSubmitItems(uid, iOrderConditionID, conditionDetail, clientItems): ITWarehouseItem[] | RequestRet {
    if (!clientItems || clientItems.length === 0) {
        return { retCode: ..., message: "Custom type requires clientItems" };
    }
    const parsed = this.parseCustomConditionDetail(conditionDetail);  // 解析 "totalNumber;id1|id2|..."
    if (parsed == null) return { retCode: ..., message: "Custom conditionDetail invalid" };
    const { allowedIds, requiredTotal } = parsed;  // 白名单 + 总需求数

    const items = [];
    let totalCount = 0;
    for (const it of clientItems) {
        if (!it || it.iItemID <= 0 || it.iItemCount <= 0) {
            return { retCode: ..., message: "Invalid clientItems entry" };
        }
        if (!allowedIds.has(it.iItemID)) {  // 白名单校验
            return { retCode: ..., message: `Item ${it.iItemID} not in whitelist` };
        }
        totalCount += it.iItemCount;
        items.push({ iItemID: it.iItemID, iItemCount: it.iItemCount });
    }
    if (totalCount < requiredTotal) {  // 总数量校验
        return { retCode: ..., message: `Custom total ${totalCount} < required ${requiredTotal}` };
    }
    return items;
}
```

> **Custom 防作弊设计**：DS 侧强制校验 ① clientItems 非空 ② 每个 itemId 在白名单内 ③ 累计数量 ≥ 总需求数。白名单为空时 reject all（避免配置缺失导致客户端"任意提交"）。

### 6.5 双重扣料 removeItemsPreferBag

```ts
public async removeItemsPreferBag(uid, items, requestSource, scene, subScene): Promise<RequestRet> {

    // 2. 一次性 DS→DSM 查询背包各 itemId 数量（E_SVR_MSG_ID_WAREHOUSE_GET_ITEM_COUNT_DS）
    const itemIdList = Array.from(requiredMap.keys());
    const bagRet = await this.DSBackpackSystem.getItemCountsDS(uid, itemIdList);
    const bagCountMap = bagRet.data || new Map();

    // 3. 逐项校验：背包 + 存储箱 >= 需求
    for (const [itemId, required] of requiredMap) {
        const bagAvail = bagCountMap.get(itemId) || 0;
        const boxAvail = this.StorageBoxManagerDSSystem.getItemCount(uid, itemId);
        if (bagAvail + boxAvail < required) {
            return { retCode: DSBackpack_RemoveObjectFailed, message: `Insufficient item ${itemId}` };
        }
        const bagDeduct = Math.min(required, bagAvail);  // 背包优先扣
        const boxDeduct = required - bagDeduct;          // 剩余扣存储箱
        // 记录到 splitList
    }

    // 4. 扣背包
    const bagItems = splitList.filter(s => s.bagDeduct > 0).map(...);
    if (bagItems.length > 0) {
        const bagRemoveRet = await this.DSBackpackSystem.removeItems(uid, bagItems, requestSource, scene, subScene);
        if (bagRemoveRet.retCode !== Success) return bagRemoveRet;
    }

    // 5. 扣存储箱（逐箱子扣，若 race 欠扣则回滚）
    for (const split of splitList) {
        if (split.boxDeduct > 0) {
            // ... 扣箱子逻辑

                await this.rollbackDeductedToBag(uid, actuallyDeducted, scene, subScene);

}
```

> **双重扣料**：优先扣玩家**背包**，背包不足时再扣**存储箱（屯屯宝）**。若背包+存储箱总和仍不足，整体不扣。扣箱过程中若出现 race 欠扣（预校验通过但实际箱子不够），会触发回滚，把已扣物品加回背包。

## 八、前端设计环节总结

综合以上源码分析，互助站订单系统的前端设计可归纳为以下 **8 个设计环节**：

### 8.1 分层架构（MVVM）

严格遵循 MVVM 分层：

- **Model 层**（`MutualAidStationModel.ts`）：纯数据定义 + 枚举，不包含业务逻辑。
- **System 层**（`MutualAidStationSystem.ts`）：业务逻辑 + 网络请求 + 状态管理，通过 `@Inject` 依赖其他系统。
- **View 层**（`System/UI/*`）：ViewComponent + WindowController，负责渲染和用户交互。

每层通过**接口**（`IMutualAidStationSystem`）解耦，UI 层通过 `@Inject(TKPartyGameSystemObjectDefine.MutualAidStationSystem)` 拿到系统引用。

### 8.2 响应式数据驱动（observable）

- 核心模型 `_mutualAidStationModel` 用 `observable()` 包装，字段变更自动触发 UI 重渲染。
- 数组也用 `observable([])` 包装，通过 `length = 0` + `push` 原地更新，保持引用稳定，避免 UI 订阅丢失。
- 持有量 `CachedItemData` 也是 observable，UI 直接绑定 `.itemCount`。
- `observe(() => {...})` 用于副作用（如倒计时定时器、状态机切换）。

### 8.3 事件驱动通信

三种事件体系并存：

| 事件类型 | 机制 | 用途 |
|---|---|---|
| **系统全局事件** | `eventSys.triggerEventScopped(EventType.Default, XXXEventDefine, XXXEventScope)` | 跨系统/跨窗口广播（`ModelUpdate`、`RefreshSelect`、`TKPGOrderComplete` 等） |
| **网络事件** | `EventType.Net` + `getEventConfigs()` | GS 推送的协议消息（`NOTIFY_INFO_CHANGE`） |
| **组件事件** | `triggerComponentEvent` / `registerComponentEventHandler` | 父子组件通信（`OnMutualAidStationEntrustClick`、`MutualSubmit`、`MutualRefresh`、`MutualItemRefreshButtonClick`） |

关键事件流：

```
订单状态变化(GS推送) → onMutualAidStationEntrustsChanged → 更新模型 → triggerEvent(ModelUpdate)
                                                              ↓
                                            EntrustViewComponent / DetailViewComponent 收到后刷新
```

### 8.4 网络请求三层架构

- **普通 GS 请求**：`this.request(messageId, proto)` —— 用于 `GET_INFO`（6711）、`REFRESH`（6712）。
- **DS 请求**：`TS_MediatorComponent.sendServerRequest(...)` —— 用于提交订单（`FinishMutualAidStationEntrust`），走「Client → DS → DS 扣料 → 上报 GS」链路。
- **主动推送**：`EventType.Net` 网络事件 —— `NOTIFY_INFO_CHANGE`（6713）由 GS 主动推送。

### 8.5 状态机设计（订单状态）

订单有 6 种状态（`E_DAILY_ORDER_STATE`），UI 通过 `preStatus` 记录旧状态，`status` 记录新状态，实现状态**边沿检测**：

```ts
entrust.preStatus = entrust.status;  // 先存旧
entrust.status = element.eState;     // 再更新
```

UI 侧根据 `preStatus → status` 的跳变播放不同动画（如 `LOCK_OF_NEWBIE → RUNNING` 播放解锁动画）。

### 8.6 定时器设计（零点刷新 + 倒计时）

- **零点刷新**：10 秒轮询 → 快到零点转一次性 setTimeout → 请求后比对签名 → 最多重试 6 次。
- **倒计时**：每个订单卡片用 `observe` + `setInterval` 每秒递减 `localCountDown`，到 0 时触发 `RefreshSelect`。
- **动画保底**：提交时 2 秒 `animationTimer` 保底，防止动画卡住导致 `WaitingForAnimToRefresh` 永远为 true。

### 8.7 弹窗池与队列管理

- 主窗口打开时暂停其他弹窗队列（`TKPGPauseWindowsQueue`），关闭时恢复（`TKPGResumeWindowsQueue`）。
- 订单完成通知通过 `winPoolSys.enqueneWindowPool` 排队，避免互相遮挡。
- 小助手面板通过 `OnAssistantFacilityUIOpen/Close` 事件联动显隐。

### 8.8 防作弊设计（Client 信任边界）

- **Fixed 类型**：客户端不传材料清单，DS 自行从配置表 `sConditionDetail` 解析扣料（防客户端篡改扣料数量）。
- **Custom 类型**：客户端传自选清单，但 DS 强制校验 ① 白名单 ② 总数量，白名单为空时 reject all。
- 扣料在 **DS 侧**完成（背包优先 + 存储箱兜底），客户端无法直接发 GS 请求绕开扣料。

## 附：已发现的潜在问题（供后续优化参考）

1. **`forceUpdateItemData` 的 Custom 分支 bug**：`items.concat(entrust.submit.SpecifyItemIds)` 返回值未赋回，Custom 物品的持有量不会批量刷新。
2. **`requestMutualAidStationRefresh` 死代码**：`generateEntrust` 结果未写回 model，订单更新完全依赖 GS 的 `NOTIFY_INFO_CHANGE` 推送，此处有 `TODO` 注释待清理。
3. **时间单位不一致风险**：`generateEntrust` 里 `countdown` 用毫秒级（`lRefreshEndTime - Date.now()`），而 `getCountDownWithEndTime` 里 `endtime - CurTime/1000` 用秒级，两处口径需确认。
4. **`isReadySubmit`（Custom）口径**：统计的是「白名单内所有物品持有量总和」，与提交时玩家实际选择组合的校验口径可能不一致（提交以 DS 侧严格校验为准）。
5. **红点事件命名反直觉**：`MutalAidEntrustRedDotCompEvent` 参数叫 `lightOff`，但 `lightOff=true` 时红点显示，语义与实际相反。
6. **`getCountDownWithEndTime` 中 `endtime` 可能为 0n**：当订单刚初始化（`endtime = 0n`）时，`Number(0n) - CurTime/1000` 会得到负值。

> 以上问题均基于源码静态分析标注，是否影响线上行为需结合运行时验证。
